# Браузеры: где это работает, а где нет

Ограничивать доверие по доменам умеет только **движок Chromium**. В остальных браузерах
такой возможности нет — и честный ответ иногда «тут никак».

## Chrome, Edge, Brave, Chromium — работает

Политика `CACertificatesWithConstraints`, доверие ограничено списком доменов.

| Браузер | Идентификатор файла политики | С какой версии |
|---|---|---|
| Google Chrome | `com.google.Chrome` | 132 |
| Microsoft Edge | `com.microsoft.Edge` | 133 |
| Brave | `com.brave.Browser` | на движке Chrome 132+ |
| Chromium | `org.chromium.Chromium` | 132 |

```bash
sudo ./scripts/install-mincifry --browser edge
sudo ./scripts/install-mincifry --browser all
```

Версию движка смотрите на `chrome://version` / `edge://version`. На более старых сборках
политика будет молча проигнорирована — ошибки не будет, просто ничего не изменится.

## Safari — не работает, и обойти нельзя

Safari берёт доверие из системного хранилища macOS. Ограничить его по списку доменов нечем:
в настройках доверия keychain есть выбор по назначению (SSL, S/MIME, подпись кода),
но **не по доменам**. Либо корень доверенный везде, либо нигде.

Что можно сделать, от лучшего к худшему:

1. **Открывать такие сайты в Chrome.** Скучно, зато область доверия остаётся узкой.
2. **Яндекс.Браузер** — см. ниже, там уже всё настроено.
3. **Установить корень в системный keychain** и получить глобальное доверие. Это ровно тот риск,
   ради ухода от которого написан этот репозиторий. Если всё же решились — понимайте, на что идёте,
   и помните, что откатывается это удалением сертификата из «Связки ключей» (вкладка «Система»).

## Firefox — работает, но без ограничений

У Firefox собственное хранилище корней (NSS), политики Chromium на него не действуют.
Импорт вручную: **Настройки → Приватность и защита → Сертификаты → Просмотр сертификатов →
Центры сертификации → Импортировать**, отметить «Доверять при идентификации веб-сайтов».

Ограничить доверие по доменам в интерфейсе Firefox нельзя. Доверие будет таким же широким, как
в случае с keychain, — только внутри Firefox.

Альтернатива: включить `security.enterprise_roots.enabled` в `about:config` — тогда Firefox
начнёт брать корни из системного хранилища macOS. Но корень туда всё равно придётся положить,
то есть в безопасности вы ничего не выиграли.

## Яндекс.Браузер — работает из коробки

Корень Минцифры в него уже встроен, настраивать нечего. Если нужен рабочий доступ к банку
без возни — это самый короткий путь. Взамен вы доверяете набору корней, который выбрал
за вас Яндекс.

## iPhone и iPad

Здесь всё иначе: и Safari, и Chrome на iOS используют системное хранилище.
Нужен профиль конфигурации — Госуслуги раздают его на https://www.gosuslugi.ru/crt.
Ограничить доверие по доменам на iOS нельзя.

## Терминал: curl, wget, openssl

Политики браузера их не касаются — у каждого свой набор корней. Разово:

```bash
curl --cacert certs/russian_trusted_root_ca.pem https://example.ru
openssl s_client -connect example.ru:443 -servername example.ru -CAfile certs/russian_trusted_root_ca.pem
```

Класть этот корень в общий бандл (`/etc/ssl/cert.pem`) не советую по той же причине:
ему начнут доверять все консольные утилиты разом.
